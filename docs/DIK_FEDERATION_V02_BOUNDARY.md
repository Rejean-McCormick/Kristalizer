# Kristalizer — candidate identity links stay in staging

**Read-only interoperation boundary, 24 November 2026.** Kristalizer may
inspect source Kristals and propose KQ↔QID and KP↔PID links in isolated
staging. A lexical match, model confidence, Wikidata redirect or shared
number `KQ1001` is never enough to merge two identities or grant `exactMatch`.

Each local ID is namespaced `(namespace_id, KQ/KP)`; Wikidata Q/P is a
separate external reference and Wikidata L/S/F lexemes are distinct data.
The diK V5.11 derived registry preserves conflicting revisions for review.
Its decision file profile `/0.2` binds the SHA of the graph as well as
index, registry, crosswalk and catalog. Even a reviewed derived selection
does not authorize Kristalizer to write a canonical source.

The original Kristal, Authoring Kit workflows and all publishing gates are
unchanged. This note adds no automatic staging/build/activation behavior.
